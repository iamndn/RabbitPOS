## 2. Active Open Question for Gate G1 — `Q8`: Tabular Figures on Apple Devices (`Pre-Flight Item 6`)

### 2.1 Question Statement
Under `Override Q1`, UI labels, product names, and prose (`--font-sans`) render in the **native system font (`SF Pro Text` / `SF Pro Display`)** on Apple devices (`iOS`, `iPadOS`, `macOS`) and fall back to self-hosted **`Inter Variable`** on non-Apple devices (`Android`, `Windows`, `Linux`), whereas money, KPIs, and table amounts (`.font-num` / `.tabular-nums`) force **`Inter Variable`** on every platform.

**Question**: *On Apple devices, should money and tabular figures also use the native system font (`SF Pro`, which has native OpenType `tnum` tabular figures) instead of `Inter Variable`, so that a single row does not mix two typefaces?*

### 2.2 Comparison of Options

| Criterion | **Option A (RECOMMENDED): System Font First + `tabular-nums` (`-apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display", var(--font-inter), sans-serif`)** | **Option B (Current `Q1` Baseline): Forced `Inter Variable` Everywhere (`var(--font-inter), -apple-system, BlinkMacSystemFont, sans-serif`)** |
| :--- | :--- | :--- |
| **Typeface Consistency Within a Single Row** | **100% Unified Typeface per Platform**: On iPhone/iPad/Mac, both `"Trà đào cam sả (Size L)"` and `"45.000 ₫"` render in `SF Pro`. On Android/Windows/Linux, both label and price render in `Inter Variable`. Zero x-height, stroke-terminal, or baseline-weight mismatch within a row. | **Mixed Typefaces on Apple Devices**: Every POS cart row, receipt summary row, KPI sentence, and ledger line mixes `SF Pro` prose (`x-height ~0.52`) with `Inter` numerals (`x-height ~0.546`) on the same baseline. |
| **Vertical Column Alignment (`0–9` Digit Widths)** | **Pixel-Exact Tabular Alignment on Every Platform**: Apple's `SF Pro` natively implements OpenType `tnum` (`font-variant-numeric: tabular-nums; font-feature-settings: "tnum" 1`), giving all digits `0–9` equal advance width on Apple devices while `Inter Variable` `tnum` does the exact same on non-Apple devices (`[VERIFIED]` OpenType spec; `[UNVERIFIED]` `V8` optical check with `₫` `U+20AB` on iOS Safari). | **Pixel-Exact Tabular Alignment on Every Platform**: `Inter Variable` `tnum` (`1138/2048` advance width `[VERIFIED]` in Phase 1A) renders identical digit shapes across iOS and Android. |
| **Runtime Font Download on Apple Devices (`iPhone / iPad / Mac`)** | **`0` Bytes Downloaded (`[VERIFIED]` `@font-face` behavior)**: Because `-apple-system` satisfies all Latin, Vietnamese, digit, and `₫` glyphs locally from OS memory, iOS/macOS Safari downloads **`0` KB** of WOFF2 files (`58,508` B saved). | **`58,508` Bytes Downloaded (`48,256` B Latin + `10,252` B Vietnamese)**: Because currency strings contain digits (Latin subset) and `₫` (`U+20AB`, Vietnamese subset), Apple devices still download both Inter WOFF2 files. |
| **Implementation Complexity** | **1-line stack order change** in `globals.css` (`.tabular-nums, .font-num`) and `tailwind.config.ts` (`fontFamily.num`). | Already specified in `Q1` baseline. |

### 2.3 Recommendation & Gate G1 Decision Protocol
- **Recommendation**: **Adopt Option A** (System font stack first with mandatory `font-variant-numeric: tabular-nums; font-feature-settings: "tnum" 1;` on `.font-num` / `.tabular-nums`, falling back automatically to `var(--font-inter)` on non-Apple platforms).
- **Reason**: An authentic iOS 26 / macOS Tahoe interface never mixes `SF Pro` labels with `Inter` numbers inside the same list cell or button (`"Thanh toán • 145.000 ₫"`). Because `SF Pro` already ships first-class tabular numerals (`tnum`), Option A achieves single-typeface harmony on every platform, eliminates `58,508` bytes of unnecessary font downloads on iPhones/iPads/Macs, and keeps `Inter Variable` `tnum` 100% active on Android, Windows, and Linux.
- **How Decided at Gate G1**: Section 1 of `/ui-gallery` (`Commit 2D`) renders a 6-row Vietnamese POS Cart + Financial Reconciliation table (`45.000 ₫`, `1.250.000 ₫`, `-1.089.012 ₫`, `+14,8%`) with an instant **`[Option A: SF Pro tnum | Option B: Inter tnum]`** segmented toggle so the owner can inspect both on a real iPhone at **Gate G1** (`05-execution-plan.md` §3.2) before Phase T3 begins.
